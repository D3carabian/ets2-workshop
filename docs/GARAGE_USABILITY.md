# 车库可用性与驾驶员信息

## 行为与数据边界

- 顶栏只显示语言选择器；自动存档开关只响应方框和标题，灰色说明和空白不触发扫描。再次点击已选候选会取消选择并收起参数对比。
- 另存名称默认使用本地日期时间（含毫秒），同轮关闭弹窗、切换保存方式和失败重试保留手工输入。成功保存或重新打开存档后开始新一轮命名。备份目录与恢复保护不变。
- 驾驶员归属按车库 `vehicles[i]` / `drivers[i]` 同槽匹配，使用已有 unit 索引校验引用。空槽、玩家、雇员、无法识别分开显示；重复、冲突、错误类型和损坏数组不猜测归属。
- 当前玩家车在前，未确认雇员的车辆居中，确认雇员的车辆在后；每组保留存档原顺序。前端按姓名和编号搜索，改装预览与撤销保留驾驶员信息。
- 英文姓名只读本机游戏的 `locale/en_gb/driver_names.sii`：`driver.N` 对应十进制 `name[N]`，不是文件行号。去掉名字前的性别标记 `+`。不分发游戏姓名表；未知姓名显示编号。
- 姓名缓存独立版本为 1。旧目录不因此失效，仍可编辑；“建立 / 更新目录”会补读姓名，后续命中缓存不再解包。姓名读取失败不阻止配件目录使用，下次更新会重试。

## 性能设计与测量

归属识别只扫描一次车库和槽位，使用哈希表查询、记录冲突；不按每台车重新扫描驾驶员。前端使用三个数组稳定分组，不做比较排序。姓名读取只发生在目录建立阶段，不发生在开档、选车和渲染阶段。

2026-10-04，本机 AMD Ryzen 9 9950X3D（16 核 / 32 线程），Rust Release 构建；全部存档和姓名为内存合成数据。30 轮测量取中位数，夹具创建和结果释放不计时：

| 驾驶员与车辆数 | SII 解析 | 驾驶员归属 | 完整车辆清单 |
| --- | ---: | ---: | ---: |
| 1,000 | 4.16 ms | 0.63 ms | 2.41 ms |
| 5,000 | 20.46 ms | 4.28 ms | 14.61 ms |

归属阶段低于本机目标 50 / 250 ms。结果不代表所有设备，也不是完整界面打开时间；原生开档测量单独记录。普通 CI 只验证规模与正确性，不使用易受机器负载影响的硬计时断言。

复现：

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml --test drivers
cargo test --locked --release --manifest-path src-tauri/Cargo.toml --test drivers -- --ignored --nocapture
node --test scripts/garage.test.mjs
```

实际游戏只读检查还确认本机英文姓名表包含 355 项；该字典未写入测试夹具或仓库。

前端稳定分组在 Node.js 22 中预热后测量 30 次，中位数分别为 0.032 / 0.040 ms。归属识别加分组仍低于目标。

## 原生界面验证

使用实际 Tauri WebView、隔离的配置和完全合成的存档；本次功能报告没有替换真实存档。原版基线来自已验证的 v0.3.0 发布包，新版使用 Release 构建，在同机使用相同生成规则的样本，各测三次按钮打开至车卡出现的中位数（包括 RPC、解析、序列化和渲染）：

| 车辆及驾驶员数 | v0.3.0 Release | 本次 Release |
| --- | ---: | ---: |
| 1,000 | 110.08 ms | 106.81 ms |
| 5,000 | 194.93 ms | 214.88 ms |

1,000 的小幅差异可能来自测量波动；5,000 增加约 20 ms，未出现按车辆重复扫描驾驶员导致的二次增长。Debug 开档数据不能与 Release 混作性能结论。

自动化覆盖：自动存档灰色说明与空白点击不触发 discover，标题和空格键切换有效；重复点击候选取消对比；非法电动引擎候选不能加入；预览和撤销保留驾驶员；连续另存名称变化；手动名称在模式切换和真实源文件变化导致的保存失败后保留；原始合成存档保持不变。

布局检查覆盖中英文、1080×720 / 1440×900 / 1920×1080 CSS 视口和 DPR 1 / 1.25，共 12 张原生 WebView 截图。对齐误差小于 1 CSS px，分页与加入按钮间距 12px，没有水平溢出。DPR 1.25 的 1080×720 CSS 视口截图为 1350×900 物理像素；这项验证不等同于修改宿主 Windows 的系统缩放设置。

## 独立复查

独立上下文 reviewer 从差异重新审查，并亲自连接隔离的原生 Tauri 窗口操作、截图和查看图片，结论 PASS。复查了中英文最小窗口、实际 CSS 125% 放大，以及相应逻辑尺寸 / DPR 的等效场景；没有修改宿主 Windows DPI 设置。

复查实际点击确认：灰色说明和空白产生 0 次 discover，标题与空格键各产生 1 次；非法电动引擎不能加入清单；合法柴油替换、撤销、雇员姓名搜索、驾驶员身份保持及存档名称均通过。测试实例已经关闭。

已知显示边界：窗口声明的最小尺寸为 1080×720 **逻辑像素**。将 1080×720 物理像素按 125% 换算成 864×576 CSS 像素的额外压力场景低于该宽度，出现约 60 CSS px 横向溢出；复查确认滚动后关键操作仍可点击。本次没有扩大到更小窗口的布局重构。
