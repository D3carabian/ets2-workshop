# 存档与配件目录性能：独立审查

审查对象为 `6945e06`（基线 `2f3476f`）及随后修复。用户要求加快存档列表刷新和游戏资源准备，并允许选择是否包含自动存档。

审查由不继承实现对话上下文的独立 subagent 执行，从原始需求和项目规则读代码、构造合成复现。首轮结论为 **request_changes**，发现三项 P2；修复后复审结论为 **PASS**。不以已有测试通过代替审查，也不将复审通过解释为不存在任何其他缺陷。

| 问题与触发条件 | 修复与回归证据 |
| --- | --- |
| `.sii → def/common.inc → 树外文件`：已加载 `.inc` 未继续遍历，快速构建静默漏掉整个定义 | 所有被引用文件均进入去重队列，不按扩展名跳过已加载引用；内存与完整磁盘扫描逐字段一致。结果缓存版本升至 2，旧解析结果重建。 |
| 包含 → 隐藏 → 再次包含未变化的 autosave：名称缓存被清掉，再次解码 | 隐藏期间保留名称；重新显示时仍核对内容、改名和已删除槽。合成计数断言确认未变化名称仅解码一次。 |
| 首次构建期间独占锁定 `locale.scs`：失败名称结果被持久化，解锁后点击更新仍无法恢复 | 带语言读取警告的结果可用回退名称查看，但不进入热缓存；解锁且资源时间未变时重试恢复双语名称，恢复后才可热命中。 |

复审者逐项核对修复，并独立执行库测试：31 通过，4 个需安装游戏的用例默认忽略。审查过程中只使用合成数据，没有修改真实玩家存档；临时复现代码已清理，稳定回归测试保留在 `discovery.rs` 和 `catalog.rs`。

主 agent 的完整 `scripts/build.ps1 -CheckOnly` 通过：62 项 Rust、15 项前端、10 项 Node 选择器、21 项打包检查；9 份来源许可与 384 个依赖的 623 份许可文本校验通过。实际桌面自动存档筛选与首次向导回归通过，隐藏后重新显示耗时 52 ms（包含 UI 操作）。最终只读游戏验收再次确认 26,382 条定义逐字段一致，冷构建 13.26 秒、热构建 0.264 秒。性能测量范围与限制见 [存档列表记录](SAVE_LIST_PERFORMANCE.md) 和 [配件目录记录](CATALOG_PERFORMANCE.md)。
